# Spike 01: nginx vs Caddy as Kiln's web server (Windows first)

**Feeds:** [ADR 0005](../adr/0005-web-server.md) · **Time box:** 3 days · **Runs on:** the dev machine (user space only)

## Questions to answer

1. **PHP on Windows.** Can each server drive a pool of `php-cgi.exe` FastCGI workers on loopback
   TCP reliably, including worker crashes, `PHP_FCGI_MAX_REQUESTS` recycling, and load spread
   across several workers?
2. **TLS from our CA.** Can each server use certificates issued by Kiln's own
   *name-constrained* CA (permitted subtree `.test`)? For Caddy, either by loading our root
   into its PKI app or by giving it per-site cert/key files. Are HTTP/2 (and HTTP/3 on Caddy)
   negotiated?
3. **Reconfiguration.** What does adding or removing a site cost? Measure dropped or failed
   requests while reconfiguring under load: nginx `-s reload` vs a Caddy admin API `POST /load`.
4. **Config generation.** How large and how testable is the generator for: parked site,
   linked site with a custom docroot, per-site PHP version, reverse proxy site, and user
   override snippet?
5. **Footprint.** Binary size, idle RSS, RSS under load, and startup time.
6. **Operations.** Windows quirks (path quoting, drive letters, spaces, long paths, Unicode
   folders), log rotation, behavior after sleep/resume.
7. **Supply chain.** Release cadence, signed artifacts, and how we would verify downloads.

## Setup (all portable, in `spikes/web-server/.cache/`)

| Item | Source | Verification |
|---|---|---|
| nginx for Windows, current stable | nginx.org/download | PGP signature (`.asc`) with nginx signing keys |
| Caddy, current release, windows_amd64 zip | GitHub releases caddyserver/caddy | `checksums.txt` + its signature |
| PHP 8.4 NTS x64 | windows.php.net/downloads/releases | SHA-256 from the release page |
| Composer (to create the test app) | getcomposer.org | published SHA-384 installer check |
| `oha` load generator | GitHub releases hatoo/oha | checksum |
| Test CA + leaf certs | generated by a small Rust spike tool (`rcgen`), Name Constraints `.test` | n/a |

Test apps: a fresh Laravel app, a static site with large assets, and a WordPress install with
SQLite, to exercise front-controller rewrites.

**Networking:** both servers bind `127.0.0.1:8080` / `127.0.0.1:8443`, one at a time.
Requests use `curl --resolve blog.test:8443:127.0.0.1` and `oha --connect-to`, so no DNS or
hosts changes are needed. **Herd keeps running untouched on 80/443.**

## Measurements

| Metric | Method |
|---|---|
| Throughput and p50/p99 latency | `oha -z 30s -c 32` against Laravel `/` and a static 1 MB asset, 3 runs each |
| PHP worker scaling | 1, 4 and 8 php-cgi workers. Throughput and errors |
| Reload safety | Under `oha` load, add and remove 20 sites in a loop. Count non-2xx responses and resets |
| Crash recovery | Kill a php-cgi worker mid-load. Count errors and time to recovery |
| TLS | `openssl s_client` / `curl -v --http2` / `--http3` (Caddy). Verify the chain against our root only |
| Footprint | Binary size; `Get-Process` working set idle and under load |
| Config generator | Lines of Rust plus template for the 5 site kinds; snapshot tests written |

## Decision criteria (weights)

| Criterion | Weight |
|---|---|
| Reload safety (zero dropped requests) | 25 |
| Works with our name-constrained CA without reimplementing PKI | 20 |
| php-cgi pool reliability on Windows | 20 |
| Generator simplicity and testability | 15 |
| Familiarity and user customization story | 10 |
| Footprint and performance | 10 |

A difference of under 10 points defaults to **nginx** (more familiar to PHP developers and
lower risk), unless Caddy removes a whole component, such as the cert issuance or reload
code.
